# Markuplint `pretenders.auto` false positives

This project reproduces false positives in Markuplint **5.0.0** when `pretenders.auto` is enabled.

## Run

Requires Node.js 24 or later.

```sh
npm ci
npm run control
npm run reproduce
npm run scan
```

`control` reports **0 problems** with `auto: false`. `reproduce` reports **5 errors and 2 warnings** with `auto: true`; it exits with code 1 as expected. `scan` prints the component mappings generated by Markuplint.

| Example | What the component renders | Reported error |
| --- | --- | --- |
| `Button` | `type` always resolves to `submit`, `reset`, or `button` | `no-invalid-attr-value` |
| `Tab` | `tabIndex` is either `0` or `-1` | `no-invalid-attr-value`, `a11y/tabindex-restrict` |
| `Chip interactive={false}` | Renders a `span` next to one `input` inside a `label` | `html-standard/label-no-multiple-controls` |
| `Picture` | Renders `picture > img` | `html-standard/permitted-contents`: missing `img` |

## Why this happens

The following behavior is visible in the Markuplint 5.0.0 source ([commit `c99706f`](https://github.com/markuplint/markuplint/commit/c99706fda4c186aeb87b521eaabc5208ac144bbd)):

1. The scanner collects string literals inside a dynamic expression and also generates an attribute without a value. Markuplint then treats that missing value as `''`, which causes the `type` and `tabIndex` errors. See [attribute scanning](https://github.com/markuplint/markuplint/blob/c99706fda4c186aeb87b521eaabc5208ac144bbd/packages/@markuplint/pretenders/src/jsx/get-attributes.ts), [mapping creation](https://github.com/markuplint/markuplint/blob/c99706fda4c186aeb87b521eaabc5208ac144bbd/packages/@markuplint/pretenders/src/jsx/create-identify.ts), and [DOM conversion](https://github.com/markuplint/markuplint/blob/c99706fda4c186aeb87b521eaabc5208ac144bbd/packages/@markuplint/ml-core/src/ml-dom/node/element.ts).
2. The scanner keeps only the first element it finds for a component. It maps `Chip` to `button` and misses the `span` branch. See [mapping storage](https://github.com/markuplint/markuplint/blob/c99706fda4c186aeb87b521eaabc5208ac144bbd/packages/@markuplint/pretenders/src/pretender-director.ts).
3. The scanner detects a `children` slot but does not keep elements that a component always renders inside itself. The generated mapping for `Picture` therefore has no `img`. See [child detection](https://github.com/markuplint/markuplint/blob/c99706fda4c186aeb87b521eaabc5208ac144bbd/packages/@markuplint/pretenders/src/jsx/get-children.ts).
